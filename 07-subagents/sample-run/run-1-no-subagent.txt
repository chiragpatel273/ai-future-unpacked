**Bug report**

1. **SAVE10 gives no discount when the cart has a sale item**
   - File: `shop/rules.py`
   - Function: `percent_off`
   - Line: the block at the top of the function:
     ```python
     # Sale items are already discounted, so coupons don't stack on them.
     if any(i.on_sale for i in items):
         return 0.0
     ```
   - Cause: `percent_off` bails out and returns 0.0 for the *entire* cart whenever *any* item is on sale, instead of skipping only the sale items when computing the percentage. So a single sale item (e.g., the $11.99 Water Bottle or $12.50 Phone Case in the catalog) kills the coupon for the whole order.

2. **US order of exactly $50.00 still pays shipping**
   - File: `shop/shipping.py`
   - Function: `shipping_cost`
   - Line: `if free_over is not None and amount > free_over:`
   - Cause: the comparison is strict `>`. "Free shipping from 50 dollars" means the threshold is inclusive, so a cart of exactly 50.00 should be free, but `50.0 <= 50` falls through and the 4.99 rate is applied.

3. **Order email shows the per-unit price on the mug line, not the line total**
   - File: `shop/emails.py`
   - Function: `order_confirmation`
   - Line: `lines = "\n".join(f"  {i.qty} x {i.name}  ${i.price:.2f}" for i in order.items)`
   - Cause: the format string prints `i.price` (unit price) instead of the line total ($i.quantity × i.price$). `Item` already has a `line_total()` helper (`shop/cart.py`) that `Cart.subtotal()` uses — the email just didn't. As written, "3 × Coffee Mug" displays one mug's price rather than 3 × that price.
